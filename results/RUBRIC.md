# Reporting-quality rubric for bibliometric and systematic reviews (v1, 17 Oct 2026)

Purpose: score how re-runnable a published bibliometric or systematic review is from what it reports. This is a reporting-quality rubric, not a validity rubric: it asks whether a reader could repeat the search and the analysis, not whether the conclusions are right.

## Items and anchors (each scored 0, 1 or 2; "NA" where the item cannot apply)

| Item | Name | 2 | 1 | 0 | Source |
|---|---|---|---|---|---|
| R1 | Database(s) and platform | Every database named (and index or platform where it matters, e.g. Web of Science Core Collection with indexes) | Named only generically ("databases such as") or some missing | Not stated | PRISMA-S 1; BIBLIO 6 |
| R2 | Search string as run | One Boolean string with operators and field scope (title/abstract/keyword) that could be pasted into the database | Terms or a Boolean expression without field scope, or several strings with no statement which produced the count | No terms | PRISMA-S 8; BIBLIO 7 |
| R3 | Date the search was run | Day, or month and year, of execution | Indirect only (URL access date, "up to October 2023" for the final year) | Coverage years only, or nothing | PRISMA-S 13; BIBLIO 7; PRIBA 5c |
| R4 | Limits and restrictions | All limits stated (years, language, document type, subject filters) and at least the main one justified | Stated, not justified; or incomplete | Not stated | PRISMA-S 9; BIBLIO 7, 8 |
| R5 | Eligibility criteria | Explicit inclusion and exclusion criteria that a second person could apply | Criteria vague, or only database filters | None | BIBLIO 9; PRISMA 2020 5 |
| R6 | Record counts per stage | Counts at identification, de-duplication, screening, eligibility, inclusion (flow diagram or table) | A start and an end number only | None or a single number | PRISMA-S 15; PRISMA 2020 16a; BIBLIO 13 |
| R7 | Cleaning and screening steps | Record-level and term-level cleaning described (de-duplication method or software, thesaurus or synonym merging, who screened) | Steps named without method, counts or person | None | PRISMA-S 16; BIBLIO 10; Donthu 2021 |
| R8 | Software with versions | Every tool named with version | Names only, or some versions | None | PRIBA 9 (split) |
| R9 | Analysis parameters | Thresholds and settings for each network or map reported (minimum occurrences, normalisation, clustering method) | Some reported | None | PRIBA 9 (split); BIBLIO 12 |
| R10 | Data and code shared | Records and code deposited in a repository with a persistent link | Statement only ("on request", "restrictions apply", checklist as supplement) | Nothing | PRIBA 18; PRISMA 2020 27 |

Scoring rules
- Score what the text says, with a verbatim quote of 40 words or fewer and the PDF page. Quotes are machine-checked against the extracted text (`code/rubric_scores.py` aborts if a quote is absent).
- A figure or flow diagram counts if I viewed it (images rendered and read for Sethi 2024, Zournatzidou 2025, Fotova Cikovic 2025).
- Items that cannot apply (a narrative systematic survey with no software analysis has no R8 or R9) are NA and removed from that paper's maximum.
- Percent score = points / (2 x applicable items). The "core" score uses the seven items Sean listed (R1 and R3 together are "database and date", R2 string, R6 counts, R7 cleaning, R8 software versions, R10 data).
- Internal inconsistencies are logged separately from scores (a review can report every item and still contradict itself).

## Limits of the rubric
- One coder (an AI assistant) for the manual scores. A regex-based second coder was run as a sanity check (`results/auto_vs_manual_summary.json`): 83 percent raw agreement, kappa 0.37 on 53 judgements; kappa is low because most items are reported at least in part. This is not a reliability estimate. Sean should double-score a subset himself before publishing; the long file gives the evidence for every score so each can be challenged.
- BIBLIO targets biomedical bibliometric reviews; PRISMA-S targets medical-style searches. Their items are adapted to a business-and-economics setting where "search" is a Scopus or Web of Science keyword query. Item weights are equal, which is a choice, not a finding.
- Only 5 of the 15 reviews could be scored from full text (see `results/REVIEWS-15-TABLE.md`); the other ten are coded at abstract level only.
